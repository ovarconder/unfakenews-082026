# AGENT — หมายเหตุเรื่อง Workflow Terminal / Auto-run / Output return

> ไฟล์นี้สำหรับ **Agent (AI)** อ่านก่อนเริ่มงานใน session นี้
> เป็นบันทึกข้อตกลงการทำงานร่วมกับผู้พัฒนา (developer) บนโปรเจกต์นี้
> โปรเจกต์: UnFake News — Next.js 14 (App Router) / Supabase / Vercel

---

## 1. เป้าหมายการทำงานที่ผู้พัฒนา (human) ต้องการ

ผู้พัฒนาต้องการให้ Agent ทำงานได้ **ลื่นไหลคล้ายกับ Continue บน VSCode (Desktop)** กล่าวคือ:

1. **run terminal ได้เอง** — คำสั่งถูก execute ทันที ไม่ต้องพึ่งการกดอะไรเพิ่ม
2. **output ส่งกลับมาที่หน้า Agent / Chat โดยตรง** หลังรันเสร็จ
   - ไม่ไปจอด/กดค้างที่ "หน้าต่าง Terminal" ของ IDE
   - Agent เห็นผลลัพธ์เพื่อนำไปวิเคราะห์/ตอบต่อได้ทันที
3. **รันคำสั่งแบบ automatic** — ไม่มีขั้นตอนกลาง เช่น ต้องให้ user กด Enter หรือกดปุ่ม confirm ระหว่างทางซ้ำซ้อน

---

## 2. ปัญหาที่พบในสภาพแวดล้อมนี้ (Codespace / Continue remote)

- การเรียก เครื่องมือรันคำสั่ง (เช่น `run_terminal_command`) มักถูกแค่ **"พิมพ์คำสั่งค้างไว้"** ที่หน้าต่าง Terminal
  แทนที่จะ execute แล้วคืน output เข้ามาที่ chat
- ผลลัพธ์ (stdout/stderr) **ไม่ถูกส่งกลับมา** หรือ capture ไม่ครบ → Agent ตาบอด ไม่เห็นผล
- บางกรณีถูกส่งออกมาเป็น **action ที่ต้องให้ user กด "Accept" (ปุ่มสีฟ้า)** ก่อนจึงจะลงมือจริง
- ตัว Agent **ไม่สามารถ auto-click ปุ่ม Accept / กด Enter แทน user ได้** เพราะเป็น UI ฝั่ง user
  (เว้นแต่จะตั้งค่า auto-accept ได้จากฝั่ง Continue config)

---

## 3. แนวทางปฏิบัติสำหรับ Agent (ให้ทำตามนี้)

ให้ยึดหลัก **ลด friction ให้ user มากที่สุด** โดยเฉพาะเรื่อง terminal:

1. **ถ้าสั่งรันคำสั่งใด ๆ ให้ออกแบบให้ result กลับมาใช้ได้ทันที** เช่น
   - แต่ละคำสั่งพิมพ์ทีละคำสั่งสั้น ๆ ชัดเจน รันจบทีละขั้น
   - ไม่ใช่ส่งหลาย ๆ คำสั่งซ้อนกันในครั้งเดียวจน user สับสน

2. **ถ้า output กลับไม่มาที่ chat** (เช่น env นี้):
   - **อย่าเดา/สมมติ** ว่าคำสั่งสำเร็จ เพียงเพราะสถานะแสดงว่า "executed"
   - ควรตรวจสอบผลด้วยวิธีที่ Agent มองเห็นได้ เช่น อ่านไฟล์ผลลัพธ์/ตรวจไฟล์ที่ควรถูกสร้าง
   - หากต้องพึ่ง terminal มากก็ควรแจ้ง user ล่วงหน้า

3. **ควรใช้เครื่องมือที่ทำงานบน disk โดยตรง** (สร้าง/อ่าน/แก้ไขไฟล์)
   แทนการพึ่ง terminal เพื่อหลีกเลี่ยงปัญหาค้างที่หน้าต่าง/ผลไม่กลับ

4. **เรื่องปุ่ม Accept (สีฟ้า):**
   - ทุก action ที่ Agent เรียกมีโอกาสต้องการให้ user กด Accept
   - ให้ **อธิบายสั้น ๆ ล่วงหน้า** ว่า Agent จะทำอะไร แล้ววาง action ทีละชุด
   - **รวมงานให้เป็นชุด ๆ** เพื่อให้ user กด Accept น้อยครั้งที่สุด
   - **หลีกเลี่ยงการใช้เครื่องมือที่ต้องให้กด Enter ที่หน้าต่าง terminal เพิ่มอีกชั้น** (ถ้าทำได้ให้ใช้วิธีอื่น)

---

## 4. จุดที่ควรตรวจสอบ/แก้ที่ฝั่ง Continue config (นอกโปรเจกต์)

> ⚠️ หมายเหตุ: ตำแหน่งนี้อาจถูกจำกัดสิทธิ์ (security block) ให้ Agent ไม่สามารถอ่าน/แก้ได้
> หากถูก block ให้แจ้ง user เพื่อให้ user ไปจัดการเอง หรือตรวจสอบด้วยตนเอง

- ไฟล์หลักของ Continue:
  - `~/.continue/config.yaml`
  - `~/.continue/config.ts`
  - `~/.continue/.continuerc.json`
- ประเด็นที่ควรหาค่าที่เกี่ยวข้อง:
  - **auto-accept / auto-run tool calls** (ให้รันโดยไม่ต้องกด Accept)
  - **output capture ของ terminal** ให้ result ส่งกลับมาเข้าที่ chat
  - **ใช้ "terminal mode" ที่คล้าย desktop** (exec แล้ว return output) แทนการพิมพ์ค้างหน้าต่าง

> ถ้าจัดการตรงนี้ได้ อาการ "ต้องกด Accept/Enter ซ้ำซ้อน" กับ "output ไม่กลับ"
> จะลดลงหรือหายไป ซึ่งตรงกับเป้าหมายในหัวข้อ 1

---

## 5. ภาษาและการสื่อสาร

- ให้สื่อสารกับ user เป็น **ภาษาไทย**
- ตอบให้ตรงประเด็น ไม่เวิ่นเว้อ ไม่ต้องมานั่งแปลข้อความผู้ใช้

---

## 6. สรุปสั้น ๆ สำหรับ Agent ประจำ session

- user ต้องการให้ Agent รันงานได้เอง output กลับมาตรง ๆ ไม่กดซ้ำซ้อน
- Agent ทำได้เฉพาะที่ตัวเองควบคุม: วาง action เป็นชุด ใช้เครื่องมือบน disk ให้มาก
  หลีกเลี่ยง terminal ที่ output ไม่กลับ และอธิบายสั้น ๆ ก่อนทุก action
- ส่วนที่ต้องพึ่ง config Continue (auto-accept / capture output) อยู่ภายนอกโปรเจกต์
  ถ้าแตะไม่ได้ให้แจ้ง user ชัดเจน
